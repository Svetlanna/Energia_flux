prediction /prediction.py

Trouve et charge le modele le plus recent dans le dossier donne.
  # glob.glob() renvoie la liste des fichiers qui correspondent a un motif.
  # Le "*" remplace n'importe quelle partie du nom (ici, la date/heure).
      # Le nom des fichiers contient la date au format AAAA-MM-JJTHH-MM-SS.
    # Trier ces noms par ordre alphabetique revient a les trier par date,
    # car ce format ecrit les nombres du plus "grand" (annee) au plus
    # "petit" (secondes) -> l'ordre alphabetique suit l'ordre chronologique.
      # Le dernier element de la liste triee est donc le plus recent.
  Calcule une prediction de consommation a partir d'un dict d'entrees.
    on construit un DataFrame a une seule ligne, avec les colonnes
    # DANS LE MEME ORDRE que lors de l'entrainement. Sinon le modele
    # se trompe de colonne (ex. il croit que "eolien" est "heure").

    # Le modele est charge UNE SEULE FOIS, au demarrage du service.
    # Le recharger a chaque requete serait lent (relire un fichier a chaque
    # appel) et inutile (le fichier ne change pas entre deux requetes)

        Microservice de prediction - API FastAPI.

        Ce fichier rend le modele de prediction accessible par le reseau,
        sous forme d'une petite API web
         Un autre service (comme le Gateway Express) pourra lui envoyer une requete pour obtenir une prediction
        sans avoir besoin d'executer du code Python lui-meme.

        Au demarrage du service :
          . le modele le plus recent est charge depuis le dossier models/
          .si aucun modele n'est trouve, le service demarre quand meme,
            mais repondra une erreur claire (503) a chaque demande de
            prediction, plutot que de planter completement

        Route disponible :
          POST /predict
            Recoit les donnees d'entree en JSON (heure, jour, meteo, etc.),
            et renvoie la prediction de consommation en MW, avec la version
            du modele utilise et l'heure de la reponse.
